# Knowledge Workbench 桌面开发预览版

基于固定版本 Code - OSS 源码构建，提供独立用户目录和内置知识扩展。当前已验证 Linux x64 的实际桌面运行，不是浏览器页面或要求用户安装到微软 VS Code 的插件演示。

完整方向见 [产品设计草案](../knowledge/DESIGN.md)。此页只记录已经实现的能力及其边界。

## 运行

当前机器已经完成源码、依赖、Electron 和内置扩展构建，直接在仓库根目录执行：

```bash
# 打开指定目录，路径有空格时加引号
npm start -- "/absolute/path/to/your/knowledge"

# 或先启动，再在工作台中选择目录
npm start
```

相对目录以启动命令的当前目录为基准。首次打开工作区时，需要在原生信任提示中确认是否信任；知识扩展不在未信任的工作区内启动。

应用使用自有名称和 `.desktop/user-data` 配置，不复用当前 VS Code 的设置、登录或用户扩展。已禁用默认 Copilot Chat、上游 API 测试扩展、遥测与自动更新，未配置 Visual Studio Marketplace。

这是可运行的源码开发版，不是已经签名、安装打包或配置好自动更新的发行产品。Windows 和 macOS 的构建与启动路径尚未实机验证。

## 第一次从干净检出构建

需要 Git、网络和上游要求的 **Node.js 24.22.1 或更新的同主版本 Node 24**。普通运行与本项目测试可使用 Node 24；准备上游源码时会校验更精确的版本。

Linux 构建前置条件以 [Code - OSS 官方说明](https://github.com/microsoft/vscode/wiki/How-to-Contribute#prerequisites) 为准。Debian/Ubuntu 通常需要：

```bash
sudo apt-get install build-essential g++ libx11-dev libxkbfile-dev libsecret-1-dev libkrb5-dev python-is-python3
```

然后：

```bash
npm run desktop:prepare
npm start -- "/absolute/path/to/your/knowledge"
```

准备脚本会：

1. 浅克隆 [固定源码基线](./upstream.json)，校验完整提交哈希；不会重置已有的其他检出。
2. 写入自有产品配置，应用 [少量兼容补丁](./patches)。
3. 安装锁定的扩展依赖和上游依赖，执行上游编译器兼容头文件准备。
4. 构建工作台、内置扩展资源并下载对应 Electron。
5. 编译并安装自有内置知识扩展。

上游源码、依赖、编译输出与运行时约占数 GB，当前构建约 7.4 GB，均放在被 Git 忽略的 `.desktop/` 中。首次准备需要时间；重复执行使用上游的增量机制。脚本支持 Node 的环境代理配置，不会关闭 TLS 校验。

本机没有系统安装权限，因此此次构建把缺少的 Ubuntu XKB/Kerberos 开发包解压在 `.desktop/native/sysroot`，仅构建子进程使用这些路径，未修改系统库。其他机器建议正常安装前置条件；这个本地缓存不提交到 Git，也不是跨平台依赖安装器。

## 如何使用

### 集合与来源

左侧“知识工作区”展示所选根目录、各级子目录和文件：

- 点击目录打开集合概览，默认范围为该目录及其后代。
- 点击文件打开来源阅读标签页；重复打开同一来源复用标签。
- 每个来源展示已解析、未支持或失败状态，具体失败原因也记录在“知识处理”输出通道。
- 概览可以继续进入子集合，也可以从文件资源管理器右键使用知识相关命令。
- 当前版本只索引第一个本地工作区根目录，不提供多个根目录的联合知识视图。

根目录中的直属文件同样是来源，不会遗漏。资料保持原位置，工具不执行资料中的脚本，也不自动提交 Git 或上传正文。

### 多格式阅读

| 格式                     | 当前能力                                      | 边界                                                       |
| ------------------------ | --------------------------------------------- | ---------------------------------------------------------- |
| Markdown、文本与常见代码 | 原文、分块、行号证据、文字搜索                | 没有代码语义分析或完整 Markdown 渲染                       |
| DOCX                     | 有顺序的正文段落、表格内段落、可用脚注/页眉等 | 表格不保留单元格坐标，不是 Word 原版式；不提取嵌入图片     |
| PPTX                     | 按演示顺序读取每页文字与显式关联的备注        | 不渲染原页面、图表、动画或嵌入媒体                         |
| draw.io / DIO            | 原生节点、连线、标签和简化图形；支持压缩图页  | 复杂分组、对象包装和样式未完整还原，不把连接解释成 AI 事实 |
| PNG/JPEG/GIF/WebP/BMP    | 原图预览                                      | 没有 OCR 或视觉理解，图片正文尚不可搜索                    |

支持格式的完整扩展名由 [解析器](./extension/src/parsers.ts) 定义。旧 DOC/PPT、PDF、音视频及其他未支持格式会保留在来源列表中，明确显示未支持，可以尝试使用系统原生应用打开。

文字默认严格 UTF-8，并识别带 BOM 的 UTF-16。历史中文文件需要主动把 `knowledge.legacyEncoding` 设置为 `gb18030` 才允许回退，阅读页会显示实际编码。

### 集合内搜索与证据定位

在集合概览中输入关键词，或执行“知识：在集合中搜索”。搜索只在明确的集合范围内进行，空格分隔的词均需匹配，最多返回 100 个片段。结果的“打开证据”会打开对应文件并高亮原段落、页面或图节点。

这是确定性文字检索，不是向量检索或生成式回答。图片以及未成功解析的文件不会伪装成已经理解的知识。

### Git 演变

选择来源或集合的“历史”，可以：

- 查看当前分支第一父链最近 60 次相关提交、提交时间与说明。
- 区分当前范围是否存在未提交或未跟踪内容。
- 阅读指定提交中的文件正文。
- 用 Code - OSS 原生差异编辑器对照“选定提交的提取文字结构 ↔ 当前磁盘内容”。
- 查看同一区间的原始 Git 差异。

Git 操作只读，不切换分支、不执行外部 diff/textconv、文件系统监视脚本或 LFS 下载。历史读取走 Git 对象，不覆盖当前文件。工作区只打开仓库中的一个子目录时，历史操作也限定在选定范围。

原生对照内容是打开比较时的工作区快照，之后修改文件需要重新发起比较；每次比较会重新读取当前文件，不复用上次的工作区正文。

当前不追踪重命名前的旧路径，不提供已删除文件入口、历史图片预览、分支切换或相邻提交对照。原始 Git 差异不包含未跟踪文件。Git LFS 指针、没有提交、非 Git 目录或缺少对象会明确报错，不生成假的历史结果。

提交说明不是经过验证的动机；本版没有 AI 变化归因、历史问答或冲突判断。

### 变化与限制

- 观察允许范围内的文件变化，延迟合并后重新扫描；修改、移动和删除会反映在索引中。
- 已打开的阅读页显示“来源可能过时”提示，需要重新打开以读取最新内容；不会把旧内容静默当成新内容。
- 索引在当前扩展宿主内存中，启动重新扫描，不使用早期实验版的 SQLite 数据。
- 默认跳过隐藏条目、符号链接以及 `.git`、`.desktop`、`.knowledge`、`node_modules`、`offline` 等配置排除目录。显式选中的工作区根目录是授权读取起点，仍需自行确认其内容适合读取。
- `knowledge.excludeDirectories` 可调整目录名排除规则。当前未实现 Git ignore 全语义匹配、自动脱敏或历史内容保留策略。
- 每份文件最多 16 MiB，每次扫描最多 5,000 个文件或 10,000 个条目；达到限制会提示结果不完整。
- ZIP/XML 解析具有条目数与展开大小限制，拒绝 XML DTD/实体声明；没有调用外部 Office 或图形渲染程序。

知识卡片、自动主题归纳、通用知识图谱、语义检索和助手问答仍未实现。原浏览器版的 Ollama 功能尚未接入桌面版。

## 开发与验证

```bash
# 仅安装并验证自有扩展，不需要下载整个桌面基座
npm --prefix desktop/extension ci
npm run desktop:check
npm run desktop:test

# 自有扩展修改后同步到已经构建好的桌面
npm run desktop:sync

# 运行全部自有测试与检查
npm test
npm run check

# 已准备好 Code - OSS 和图形会话时，运行真实 Electron 桌面端到端测试
npm run desktop:smoke
```

端到端测试创建独立临时工作区与用户配置，验证集合导航、范围搜索、证据高亮、DOCX 阅读、Git 历史正文与原生版本对照，结束后关闭测试应用并清理临时资料。测试只对自己生成的资料禁用工作区信任，不改变正式启动的信任设置。

已针对两处上游产品假设保留可重放补丁：

- 默认聊天引导缺少聊天产品配置时，不在模块加载阶段崩溃；保留原服务注册，主动调用时仍报告缺少配置。
- 默认账户集成允许产品没有聊天账户提供者；读取账户返回不可用状态，主动登录明确报错。

上游保留原 MIT 许可，解析依赖遵守各自许可，本项目新增代码仍沿用仓库现有授权。当前没有完成正式发行所需的完整许可清单、签名与更新基础设施，不应把开发目录当作成品安装包重新发布。
