# Solutions 本地知识工作台

这是文档仓库向知识工具演进的第一版，不替代现有 MkDocs 站点。

> 本文只说明保留的早期浏览器实验版。当前主入口 `npm start` 已切换到基于 Code - OSS 的 [桌面知识工作台](../desktop/README.md)。完整规划见 [产品设计草案](./DESIGN.md)，桌面版与此实验版的数据和能力并不互通。

## 开始使用

安装 Node.js 24 或更新版本。仅使用 Node 内置模块与浏览器 API，无第三方包，不需要安装依赖。

在仓库根目录执行：

```bash
npm run kb -- import --legacy-encoding gb18030
npm run legacy:web
```

打开终端打印的本机地址。默认端口为 4317，也可以使用 `npm run legacy:web -- --port 0` 自动选取空闲端口。

界面可以：

- 导入项目的文档目录，查看新增、更新、未变、编码转换、跳过和失败报告。
- 添加自己的文件。同名上传视为同一来源的新版本；目录导入以绝对文件路径区分来源，和上传来源独立。
- 搜索中英文内容，点击结果定位原文行。
- 查看当前来源的局部图谱，点击概念探索其他来源。
- 显式调用本机模型，逐条查看证据和适用条件，确认或拒绝知识断言。
- 删除来源以及它派生的索引、提及和断言，不影响其他来源的证据。

本仓库包含早期非 UTF-8 的中文代码与笔记，因此示例主动启用 GB18030 回退。界面导入时也可选择“允许 GB18030 回退”；默认严格 UTF-8，带 BOM 的 UTF-16 会自动识别。编码回退可能存在歧义，请核对导入原文，转换结果会列入报告，不会修改源文件。

## 自动图谱的两种关系

### 结构性提及：无需模型

Markdown 正文中符合标识符形态的行内代码，例如 `` `NPOI` ``，会生成：

```text
某份文档 --提及--> NPOI
```

忽略 fenced code block 内的文本。每条提及保留来源、行号和原文。只按完全相同的名称合并概念（Unicode NFC 规范化），不猜测别名、同义词或同名实体的业务身份。

这是可验证的文档结构关系，**不是依赖关系，也不是根据共同出现推导出来的事实**。目前不把普通文本中的每个名词都自动当作实体。文本与代码文件可检索，但不会产生这一类 Markdown 结构关系。

每份文档最多保留前 2,000 个候选提及，每个内容块最多 40 条。图谱按来源或概念展开，每类关系最多展示 80 条，不一次展开全库。

### 语义断言：可选本机模型

先自行安装 Ollama 并准备一个适合中文和结构化输出的本地模型。工具不会安装运行时或下载模型。例如已安装 `qwen3:8b` 时：

```bash
npm run legacy:web -- --model qwen3:8b
```

在“知识审核”中点击“使用本地 AI 抽取”。也可通过 CLI 调用：

```bash
npm run kb -- list
npm run kb -- extract <document-id> --model qwen3:8b
```

默认连接 `http://127.0.0.1:11434`。可通过 `--ollama` 更改本机端口；仅接受字面量回环地址的 HTTP origin，不接受域名、外网、代理路径或重定向。导入本身从不调用模型，启动时指定模型也不自动执行抽取。

模型必须输出受限 JSON：

```json
{
  "assertions": [
    {
      "subject": "NPOI",
      "predicate": "适用于",
      "object": "Excel 导出",
      "quote": "NPOI 可用于 Excel 导出。",
      "qualifier": "仅表示原文明确说明的适用范围"
    }
  ]
}
```

只接受 `使用 / 解决 / 依赖 / 适用于 / 替代` 五种关系，证据必须是对应内容块的精确原文子串。定位行号由程序计算，不信任模型自报的位置。

**精确引用只证明这段话存在，不能证明断言正确或完整。** 所有新断言默认“待审核”，默认图谱只显示已确认的 AI 关系。可主动勾选待审核关系，候选以虚线表示。工具不提供模型自报的“正确率”。

同一来源的一次抽取全部完成且通过校验后才替换旧结果；网络、JSON、引用校验失败时保留旧结果并报错。抽取期间来源发生变化则拒绝写入。每块请求限时 120 秒、响应最多 256 KiB、最多 30 条断言；每份文档最多 30 个内容块，长文档需先拆分。模型可以合理地返回零条断言。

## CLI

```bash
npm run kb -- --help
npm run kb -- import ./your-notes
npm run kb -- search "打印机"
npm run kb -- list
npm run kb -- show <document-id>
npm run kb -- graph <document-id>
npm run kb -- graph <document-id> --include-pending
npm run kb -- review <assertion-id> accepted
npm run kb -- review <assertion-id> rejected
npm run kb -- remove <document-id>
```

用 `--db /absolute/path/knowledge.sqlite` 指定其他数据库。需要重定向纯 JSON 时直接运行 Node，避免 npm 的启动提示混入输出：

```bash
node knowledge/cli.js graph <document-id> > graph.json
```

导入是增量追加：内容未变时不重建，变更时稳定保留来源 ID、增加版本并移除过期派生数据。已经从磁盘移除的文件**不会静默从知识库删除**，需显式 `remove`。

人工审核按“来源 + 两端实体 + 关系 + 证据 + 条件 + 抽取方法”的指纹保留。相同断言重新抽取时恢复审核状态；证据或条件改变则重新待审核。删除来源时移除原文、索引、图关系；数据库可能保留不可逆的审核指纹，不包含证据原文。普通 SQLite 删除不保证存储介质上的物理擦除。

## 支持的输入与边界

- Markdown、TXT、C#、Python、JS/TS/JSX/TSX、JSON、XML/XSL、CSS、HTML、SQL、Ruby、YAML。
- 目录导入仅处理明确指定的根目录；CLI 默认项目文档目录，Web 端只能扫描启动时固定的项目文档目录，不能提交任意服务器路径。
- 每份文件最多 2 MiB，单行最多 12,000 字符，按不超过 60 行且不超过 12,000 字符切块。不支持的格式会报告跳过，解析错误会列入失败。导入存在失败时 CLI 返回非零退出码。
- 不执行代码、不执行 HTML、不跟随符号链接，跳过 `offline/`、隐藏目录与依赖目录。敏感内容仍需由使用者识别；目录排除不是自动脱敏。
- PDF、Office、图片、音视频、网页 URL 抓取、生成式问答、向量检索、实体消歧、多用户权限管理暂未实现。不把这些输入伪装成“解析成功”。
- 中文全文搜索使用字符二元分词，英文使用词项；查询词项按 AND 组合，最多 32 项、返回最多 30 个内容块。它不是语义搜索，标点不作为精确代码匹配条件。
- 不自动检测事实冲突、版本兼容或知识过时，不保证抽取完整性；目前只支持审核状态操作，不提供断言编辑或实体合并界面。

## 数据、安全与发布

默认数据保存在仓库根目录的 `.knowledge/knowledge.sqlite`，已加入 Git 忽略规则。新建数据目录权限为 `0700`，数据库文件为 `0600`。原始磁盘资料不修改；库内保留解码和换行规范化后的原文、出处与当前版本，不保留全部历史正文。

HTTP 服务只绑定 `127.0.0.1`，校验 Host / Origin，并要求 API 使用每次启动生成的会话令牌。不依赖外部 CDN、字体或遥测，不允许上传内容作为 HTML 执行。它是单用户本机工具，不是对外暴露的托管服务；不要通过反向代理公开，也不要将未脱敏数据库放入共享目录。

使用模型前确认它确实在本机运行、数据政策符合你的要求。回环地址约束不是对本机 Ollama 或其他进程行为的安全担保。该版本没有第三方云模型接口。

知识库内容不会自动进入 MkDocs 或 GitHub Pages。现有站点构建流程保持不变。需要备份时先停止服务再复制数据库；索引、提及和断言是派生数据，可以重新导入/抽取，但人工审核记录应随数据库备份。

工具源码目前沿用仓库现有 [许可证](../LICENSE)；导入第三方材料不会改变其授权，也不意味着可以公开重新分发。
